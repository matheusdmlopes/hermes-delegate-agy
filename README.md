# delegate-agy

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

**delegate-agy** is a native [Hermes Agent](https://github.com/NousResearch/hermes-agent) tool plugin that delegates complex sub-tasks, deep research, code implementation, and multi-model reviews to local [Antigravity CLI (`agy`)](https://github.com/google-antigravity/antigravity-cli) workers.

It enables the primary Hermes agent to spawn asynchronous or blocking background workers, route tasks across different models, control process execution groups, resume conversations, and queue steering follow-ups—all without running external HTTP proxies or custom bridges.

---

## 🏛️ Architecture

```text
    Hermes Agent Core
           │
           ▼
    delegate_agy (Tool Handler)
           │
           ▼
       AgyManager
    (Concurrency, Backpressure, Process Groups, JSON Streams, Disk Persistence)
           │
           ▼
    Official `agy` CLI Binary Subprocess
    (--model, --mode=plan|accept-edits, --sandbox, JSON output)
           │
           ▼
    Antigravity Native Quota / Auth / Providers
```

- **CLI-Owned Authentication**: The `agy` CLI manages its own credentials and quota; the plugin does not extract or inject provider API keys.
- **Strict Environment Isolation**: Every resolver, capability probe, and worker spawn receives the same positive allowlist (`PATH`, `HOME`, standard locale and XDG config/data/cache variables). Parent credentials, `SSH_AUTH_SOCK`, loader injection variables, arbitrary `*_API_KEY` values, and opaque version-manager state such as `__MISE_DIFF` are never inherited.
- **Safe Wrapper Resolution**: Known `mise`, `rtx`, and `asdf` wrappers are resolved to their real `agy` executable with `<manager> which agy` under the strict environment. Resolution failures stop safely with an actionable `agy_path` configuration error instead of hanging or widening the environment.
- **Zero Daemon / Bridge Required**: Direct standard POSIX subprocess management (`start_new_session=True`, `os.killpg`) with bounded supervision and automated reaper.
- **Dynamic Binary & Capability Gating**: The source path is re-resolved at spawn time, executable fingerprints invalidate stale probe-cache entries, and `agy >= 1.1.8` is verified with sanitized environment and `/dev/null` stdin.

## 📦 Installation

Clone this repository into your local Hermes plugins directory:

```bash
git clone https://github.com/matheusdmlopes/hermes-delegate-agy.git ~/.hermes/plugins/delegate-agy
```

Ensure the official `agy` CLI (>= 1.1.8) is installed and authenticated:

```bash
which agy
agy --version
agy models
```

Enable the plugin, then start or restart Hermes:

```bash
hermes plugins enable delegate-agy
hermes
```

## 🧭 Model Routing Table

When delegating, Hermes selects a `task_type` which routes to an appropriate model:

| `task_type` | Default Model | Best For |
|---|---|---|
| `simple` | `gemini-3.7-flash-low` | Fact extraction, quick classification, reading files |
| `investigation` | `gemini-3.7-flash-medium` | Diagnosis, debugging, logs inspection (Default) |
| `implementation` | `gemini-3.7-flash-high` | Writing and modifying code |
| `hard` | `gemini-3.1-pro-high` | Difficult reasoning, large-scale codebase analysis |
| `review` | `claude-sonnet-4-6` | Independent adversarial code review |
| `exceptional` | `claude-opus-4-6-thinking` | Complex architecture & deep multi-step planning |
| `cheap_second_opinion` | `gpt-oss-120b-medium` | Low-cost cross-checks and validation |

> **Note**: An explicit `model` argument (e.g. `model="gemini-3.7-flash-high"`) completely overrides `task_type` routing.

## ⚙️ Execution Modes

- **`sandbox` (Default)**: Runs `agy` with `--mode=plan --sandbox --dangerously-skip-permissions`. Plan mode and terminal sandboxing remain active; the final flag only bypasses permission prompts that cannot be answered by a headless subprocess.
- **`accept_edits`**: Runs `agy` with `--mode=accept-edits --dangerously-skip-permissions`. Allows file modifications and commands. Requires explicit opt-in via `allow_accept_edits: true` in plugin settings; disabled by default (`false`). Empty `SUCCESS` responses are treated as failures, so permission denial cannot be reported as a false success.

## ⚙️ Plugin Settings

Settings live under the plugin entry in `config.yaml`:

```yaml
plugins:
  entries:
    delegate-agy:
      settings:
        max_concurrent: 3
        max_pending_workers: 20
        max_pending_per_owner: 10
        default_timeout_seconds: 600
        max_result_chars: 24000
        max_records_in_memory: 500
        max_raw_output_bytes: 16777216
        retention_days: 30
        max_total_storage_mb: 1024
        allow_accept_edits: false
        agy_path: null
```

- `max_concurrent` bounds parallel workers executing simultaneously (1 to 10).
- `max_pending_workers` bounds total queued/running workers globally (1 to 100).
- `max_pending_per_owner` bounds queued/running workers per session (1 to 50).
- `default_timeout_seconds` bounds a print run when the call omits a timeout.
- `max_result_chars` limits the response string returned to Hermes and stored in records; the full raw output remains in the stdout artifact.
- `max_records_in_memory` limits recent terminal records kept in memory.
- `max_raw_output_bytes` limits each stdout or stderr artifact file on disk.
- `retention_days` and `max_total_storage_mb` bound terminal artifacts on disk.
- `allow_accept_edits` controls whether `accept_edits` mode is allowed (defaults to `false`).
- `agy_path` optionally pins the real executable. Normally the plugin resolves known wrappers automatically; set this only for an unsupported wrapper, for example to the output of `mise which agy`.

Use Hermes' configuration command rather than editing YAML manually:

```bash
hermes config set plugins.entries.delegate-agy.settings.agy_path "$(mise which agy)"
```

## 💾 Storage and Recovery

Records are stored in the active Hermes profile under `plugin-data/delegate-agy/runs/`; runtime leases live under `plugin-data/delegate-agy/runtime/`. Record publication is atomic, directories reject symlinks, and files use secure permissions (`0600` for files, `0700` for directories).

Each Hermes runtime holds an exclusive lease. A second live runtime does not interrupt or claim its workers. After an unclean exit releases that lease, the next runtime marks unfinished records as `interrupted`. Unlocked stale leases and orphaned temporary files are safely garbage collected.

## 🛠️ Actions Reference

- **`spawn`**: Launch a single task or up to 10 parallel tasks (`tasks: [...]`, `wait: true|false`). Transactional: pre-reserves capacity and rolls back on failure.
- **`list`**: List all worker processes owned by the current session.
- **`status`**: Get live progress, PID, PGID, and execution status.
- **`result`**: Retrieve formatted response, usage metrics, and artifact paths.
- **`wait`**: Block until target workers complete or timeout expires.
- **`stop`**: Gracefully terminate worker process groups via `SIGTERM` / `SIGKILL`.
- **`continue`**: Resume a completed conversation by its Antigravity `conversation_id`.
- **`steer`**: Queue a bounded follow-up instruction to run sequentially after the active print turn finishes.
